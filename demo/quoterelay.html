Agent rate requests — won vs lost pricing real last 12 months

These are rate-request emails sent to agents through QuoteRelay — not Moveware job files. Agents shop rates, so this count is far bigger than the job-file count above: most requests never become a job in Moveware. The rate on the losing side exists only in the quote email, which is what makes the won-vs-lost price comparison possible.

Read "confirmed booked" as a floor, not a win rate. A request counts as booked only when we can tie it to a booked Moveware job. A QuoteRelay quote does not carry the job number, and 97% of the requests in this window have no customer name on them, so most bookings cannot be tied back — they fall to "not tied to a booking" after 120 days whether they were won or lost. The conversion figure we stand behind is the book-to-quote ratio: booked Moveware job files billed to an agent ÷ the rate requests that agent sent through QuoteRelay, over the same 12 months. Both sides are plain counts Moveware and QuoteRelay already hold — nothing is matched record-by-record, nothing is excluded, and nothing waits 120 days to be called lost. Only files Moveware tagged as an agent booking count — moves that arrived through an RMC tender (Cartus, Altair) or a corporate account were never a rate request. A company with more booked agent moves than requests works through another channel and is named rather than rated. Requests from the last few months have not all had time to book. The per-quote answer arrives the moment the QuoteRelay quote number is written onto the Moveware job.

Conversion by shipment mode real last 12 months

Every rate quoted in the last 12 months — won or not — split by how it would have shipped and how it ended. "Lost" uses the 120-day rule. The percentage on each bar is booked ÷ every quote given, open ones included — an open quote has not converted yet.
